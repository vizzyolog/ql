# Контекст проекта для агента

## Что это за проект
Репозиторий содержит методические материалы для курса детского технопарка «Кванториум»:

- **Целевой документ:** `Интерактивные онлайн-приложения.docx`
- **Шаблон качества:** `example/Шакирянов М.Р. Основы работы со спутниковыми снимками в ГИС.docx` — полноценная образовательная программа (титул, аннотация, результаты, КТП, содержание, проекты, оснащение, ПО, литература).
- **Исходная рекламная методичка:** `Курс «Создай свою онлайн-игру».docx` — короткое описание идеи курса, использовано как источник технологического стека и обещаний.

## Параметры курса
- **Название:** Интерактивные онлайн-приложения
- **Объем:** 144 часа (45 теории / 99 практики)
- **Возраст:** 12–18 лет (фактическая аудитория — в основном 6–7 классы)
- **Автор:** Чернов О.А.
- **Город/год:** Набережные Челны – 2026
- **Ключевой архитектурный принцип:** авторитативный сервер (server-authoritative) — сервер является единственным источником правды об игровом мире.
- **Формат подачи:** материал даётся тематическими блоками поверхностно, с возможностью углубления для каждого ученика.
- **Итоговый проект:** ученик выбирает сам — от игры до любого многопользовательского приложения (чат, рисовалка, квиз и т.д.). Слово «игра» убрано из названия курса, но остаётся в содержании и примерах.

## Технологический стек курса
- Язык сервера: Go (goroutines, channels, mutexes)
- Клиент: HTML, CSS, JavaScript, Canvas API
- Протоколы: HTTP, REST API, WebSocket
- Базы данных: SQLite (встроенная, без сервера), файлы JSON
- Инструменты: Visual Studio Code, Git, Postman, Node.js (вспомогательно)

## Как документ генерируется
- **Скрипт:** `generate_course_doc.py` — создает итоговый `.docx` с нуля через `python-docx`.
- **Окружение:** виртуальное окружение `.venv` с установленным `python-docx`.
- **Запуск генерации:**
  ```bash
  .venv/bin/python generate_course_doc.py
  ```

## Оформление
Форматирование целевого документа копирует образец с ГИС:
- Шрифт: Times New Roman, основной текст 12 пт.
- Поля: левое 3 см, правое 1,5 см, верхнее 1,5 см, нижнее 2 см.
- Основной текст: по ширине, межстрочный интервал 1,5, абзацный отступ 1,25 см.
- Заголовки разделов: по центру, жирным, 12 пт.
- Титульная страница: шапка по центру, блоки подписей методсовета и директора разнесены в две колонки таблицы без границ.
- Разрывы страниц перед каждым крупным разделом (аннотация, КТП, содержание, проекты, требования/ПО, литература).

## Папки и файлы
- `extracted/` — вспомогательные `.txt`-экспорты документов для быстрой проверки содержимого.
- `.venv/` — виртуальное окружение Python.
- `generate_course_doc.py` — генератор целевого docx.
- `AGENTS.md` — этот файл.

## Что делать при правках
1. Вносить изменения в `generate_course_doc.py`.
2. Перегенерировать документ командой выше.
3. Проверить объем и корректность через `textutil -convert txt ...` или открытием docx.

## Важные архитектурные акценты курса
- Курс построен вокруг авторитативного сервера.
- Go изучается не ради языка, а через практику создания веб-сервера.
- Клиенты только отправляют действия и отображают состояние; игровая логика работает на сервере.
- В проектных требованиях обязательно: клиент не может «обмануть» сервер или изменить состояние игры.
- Курс покрывает полный цикл: от основ Интернета и Go до масштабирования, безопасности и тестирования распределенной системы.

## Правила для учебных примеров
- Главная аудитория практических уроков — ученики 6–7 классов. Один урок добавляет одну основную новую идею и опирается на уже пройденный код.
- Простота и предсказуемость важнее коротких или «умных» решений. Не добавлять новые библиотеки, абстракции, JSON, конфигурацию и архитектурные слои без необходимости.
- Код должен соответствовать стандартному стилю Go: `gofmt`, понятные имена, короткие функции, явная обработка ошибок, без неиспользуемых переменных и лишнего глобального состояния. Для веб-уроков использовать стандартную библиотеку, если её достаточно.
- Комментарии должны объяснять только текущее поведение и новые для ученика понятия. Команды запуска, имена папок, адреса, порты и практические задания должны точно соответствовать коду.
- Не оставлять в подсказках альтернативные адреса или команды, если в конкретном уроке это может запутать ученика.

## Обязательная проверка перед коммитом
1. Перечитать целиком каждый изменённый файл урока, а не только diff. Проверить связанные места: структуру данных, шаблон, JavaScript, подсказку в терминале, команду запуска и комментарии.
2. Для Go выполнить `gofmt`, `go vet` и сборку. Если урок должен работать на Windows, дополнительно проверить `GOOS=windows GOARCH=amd64 go build`.
3. Запустить изменённый урок и выполнить реальный сценарий пользователя: открыть страницу, проверить отображаемые данные и работу кнопок. Для HTTP API проверить метод, тело запроса, ответ и ошибочный метод. Для шаблонов убедиться, что `Execute` завершается полностью и в ответе не остаётся `{{...}}`.
4. Проверить все варианты, которые явно представлены как готовые: основной пример, изменённые задания, адреса и команды из комментариев. Не выдавать непроверенный необязательный сценарий за работающий.
5. Проверить `git diff --check`, состав staged-изменений и `git status`. Удалить созданные при проверке бинарники, логи, снимки экрана и временные профили браузера. Не включать в коммит чужие или посторонние файлы.
6. Не коммитить, пока проверки не пройдены. В итоговом сообщении перечислить, что именно проверено, и отдельно назвать любые непроверенные ограничения.
